# Spike: Rust vs tinyjs 비교 실험 (2026-10-12)

> 기록용 문서. 결론: **Rust + wry 채택.** 여기 나오는 `rust-difv/`, `tiny-difv/`, `shared/` 경로는 정리 후 삭제됐고, Rust 버전이 프로젝트 루트(`src/`)가 됐다.

PR 리뷰 도구의 기술 스택을 정하기 위한 실험. 같은 기능(자체 창 diff 뷰어)을 두 방식으로 만들어 수치로 비교한다.

## 기능 (공통)
`difv <repo>` → 자체 창이 뜨고 `git diff HEAD`(깨끗하면 `git show HEAD`)를 파일 목록 + 색칠된 unified diff로 표시.
프론트는 `shared/index.html` 하나를 두 버전이 공유한다 (Rust: `include_str!`, tinyjs: 복사).

| 버전 | 구성 |
|---|---|
| `rust-difv/` | Rust + wry 0.57 + tao 0.37 (시스템 WKWebView). git 결과를 초기화 스크립트로 주입 |
| `tiny-difv/` | tinyjs 0.50.1 (txiki.js 백엔드 + C++ launcher + 시스템 WKWebView). `tiny.api.call('diff')` |

## 테스트 항목
1. **빌드**: 클린 빌드 시간, 증분 빌드 시간, 중간 산출물 크기
2. **배포물**: 파일 개수, 크기, 단독 복사 시 실행 여부, 외부 런타임 필요 여부
3. **속도**: 실행→첫 페인트, git 실행, 데이터 전달, 렌더링 (페이지가 `DIFV_MARK`로 단계별 시간 보고)
4. **메모리**: 앱 + 자식 + 새로 뜬 WebKit 헬퍼 프로세스 RSS 합
5. **기능**: 창이 뜨는가, argv 경로를 받는가, diff가 표시되는가 (스크린샷)

재현: `./bench.sh <repo> [runs]`

## 결과 (2026-10-12, M-series Mac, macOS 26.6)

### 빌드
| | Rust | tinyjs |
|---|---|---|
| 클린 빌드 | **32초** (의존성 포함) | **0.65초** |
| 증분 빌드 (main.rs/HTML 수정) | 0.7–1.8초 | 0.56초 |
| 중간 산출물 | **target/ 242MB** | `.build/` ~0.5MB (번들용 JS 사본과 아이콘) |

### 배포물
| | Rust | tinyjs |
|---|---|---|
| 실행 파일 | **1개** `rust-difv` 1.5MB | **2개** `difv` 5.7MB(tjs+JS+HTML 내장) + `launcher` 3.1MB |
| 단독 복사 실행 | ✅ | ❌ `launcher binary not found` → 두 파일 같이 두면 ✅ |
| .app 번들 | 직접 만들어야 함 | 자동 생성 9.3MB, 서명됨 |
| 외부 의존 | 시스템 프레임워크만 (`otool -L`) | 시스템 프레임워크만 (인터프리터는 `difv` 안에 내장) |
| 실행 시 부산물 | 없음 | 매 실행마다 `/var/folders/.../T/tinyjs-*/`에 launcher 심링크와 소켓 생성 (0B). 강제 종료하면 남는다 |

### 속도 (3회 측정)
| diff 크기 | 항목 | Rust | tinyjs |
|---|---|---|---|
| 11줄 | 실행→첫 페인트 | 500–600ms (첫 회 1.2s) | 670–760ms (첫 회 1.7s) |
| | git / 데이터 전달 / 렌더 | 21–28 / 0 / ~100ms | 28–43 / 34–59 / ~27ms |
| 1,684줄 | 실행→첫 페인트 | 610–750ms | 650–720ms |
| 120,801줄 | 실행→첫 페인트 | 1.41–1.50s | 1.42–1.77s |
| | git / 데이터 전달 / 렌더 | 76–79 / 0 / 910–950ms | 86–90 / 151–157 / 700–920ms |

비교 기준은 **실행→첫 페인트**다. 단계별 수치는 진단용이다. Rust는 데이터가 즉시 오므로 WebKit 첫 프레임 대기가 "렌더"에 잡히고, tinyjs는 같은 대기가 "데이터 전달"에 겹친다. 데이터+렌더를 합치면 비슷하다 (11줄 ~100 vs ~60–85ms, 12만 줄 ~930 vs ~935ms).

### 메모리 (RSS)
| | Rust | tinyjs |
|---|---|---|
| 11줄 diff (bench 3회) | 153–163MB | 126–198MB (편차 큼) |
| 12만 줄 diff (bench 3회) | 508–536MB | 563–571MB |

프로세스별 스냅샷 (11줄, 3초 대기 후 1회, bench와 대기 시간이 달라 값이 다름):
Rust = 앱 58 + WebKit(GPU 19, Network 8, WebContent 20) ≈ 105MB /
tinyjs = 백엔드 3 + launcher 66 + WebKit(GPU 22, Network 12, WebContent 24) ≈ 127MB.
WebKit 헬퍼의 RSS는 실행마다 수십 MB씩 흔들린다.

### 기능
두 버전 모두 자체 창으로 뜨고, argv 경로(절대·상대 `.` 모두)를 받고, 같은 화면을 그림 (스크린샷 확인).
주의: 터미널에서 실행하면 두 버전 모두 창이 다른 창 뒤에 뜬다 (포커스 처리 필요).

## 해석
- **속도와 메모리는 사실상 동률.** 시간과 메모리의 대부분은 WebKit 몫이다. 12만 줄에서 둘 다 ~1.4s/~500MB인 것은 DOM 12만 개를 한 번에 그리기 때문이다. 백엔드 언어보다 **가상 스크롤(보이는 줄만 렌더)** 이 훨씬 큰 차이를 만든다.
- tinyjs는 백엔드→페이지 데이터 전달(소켓 왕복, 12만 줄에서 ~150ms)이 추가된다. Rust는 시작 시 주입이라 0.
- **차이는 빌드와 배포에서 난다.** Rust는 파일 1개 대신 빌드 32초와 target 242MB를 낸다. tinyjs는 빌드가 즉시이고 중간 파일이 ~0.5MB뿐이지만, 실행 파일이 2개다 (인터프리터는 내장이라 별도 설치 불필요).

## 2차: 왼쪽 파일 트리 추가 (2026-10-12)
`git ls-files` 전체를 트리로 표시. 변경 파일은 +/- 표시, 변경이 있는 폴더만 펼침, 자식이 하나뿐인 폴더 체인은 `a/b/c`로 합침.
백엔드는 git 호출이 하나 늘었고, 트리 구성과 렌더는 공유 프론트(`<details>`)에서 한다.

| | Rust | tinyjs |
|---|---|---|
| 코드 변경 | main.rs +2줄 | main.js +2줄 |
| 재빌드 | 1.8초 | 0.57초 |

| 저장소 (파일 / diff 줄) | 실행→첫 페인트 Rust | tinyjs | RSS Rust | tinyjs |
|---|---|---|---|---|
| kanjix (62 / 11) | 650–830ms | 740–1470ms | 148–156MB | 164–183MB |
| skills-repo (347 / 1,684) | 670–810ms | 740–880ms | 156–158MB | 169–183MB |
| 합성 bigtree (10,000 / 1,401) | 700–840ms | 830–910ms | 106–184MB | 121–200MB |
| 합성 bigrepo (200 / 120,801) | 1.51–1.65s | 1.48–1.62s | 531MB* | 568–576MB |

\* Rust bigrepo 1회차 139MB는 측정 누락으로 보인다(WebKit 헬퍼 탐지 실패). 2·3회차만 적었다.

- 1만 개 파일 트리를 그려도 DOM 생성은 ~18ms다. 첫 페인트는 트리 없을 때보다 100~200ms 늘었다.
- 이번에도 두 버전의 차이는 측정 편차 범위 안이다. 비용은 git 호출이 아니라 WebKit 렌더에서 나온다.

## 이번에 하지 않은 것
범위 인자(`main..feature`), PR 가져오기, 변경 안 된 파일 클릭 시 내용 보기, LLM 질문, 구조 diff, 구문 강조, 가상 스크롤.
